# Project Compass

Use when the task is part of a larger product/project and priority or stopping matters.

## Purpose
Separate the infinite project from the finite target currently being pursued.

```text
Ultimate Goal → Current Target → Finish Line → Work Class → Next Move
```

## Work classes
- REQUIRED: target cannot honestly be met without it.
- RECOMMENDED: meaningful quality/risk improvement, not a blocker.
- OPTIONAL: useful but low leverage for the current target.
- DEFERRED: consciously postponed and visible.
- IRRELEVANT: no material target impact.

Finding is not work. Every new finding is triaged before becoming active scope.

## Finish Line
Prefer observable obligations, not percentages. Do not average critical and cosmetic dimensions into one readiness score.

Bad: `project is 93% ready`.

Better:
```text
Current Target: Minimum Launch
Required remaining: 2
- interrupted-payment recovery
- production critical-flow verification
```

When Required remaining reaches zero and required evidence is current, Target is MET. Stop. Remaining Recommended/Optional work can be offered, not silently promoted.

## Next moves
At most three distinct choices:

```text
1. REQUIRED — action / why / finish-line effect
2. RECOMMENDED — action / why / finish-line effect
3. STOP / SHIP — when target is met
```

Recommend one. The user should not need to ask “now what?” or “when does this end?”
